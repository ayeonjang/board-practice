# 게시판 개선 실습: 검색·정렬·페이지네이션

## 1. 실행 방법

Node.js 18 이상을 권장합니다.

```bash
npm install
npm start
```

브라우저에서 http://localhost:3000 에 접속합니다. 게시글 1,000건은 서버 시작 시 인메모리 배열로 생성됩니다.

## 2. 파일 구성

- `server.js`: Express API, 1,000건 데이터 생성, 검색·정렬 및 페이지네이션
- `index.html`: 게시판 UI, 디바운스 검색, 요청 취소, URL 상태 복원
- `package.json`: Express 의존성과 실행 스크립트

## 3. API

### 오프셋 페이지네이션

`GET /api/posts?page=1&limit=10&sort=latest&search=인덱스`

검색은 제목과 본문에 대소문자 구분 없이 적용합니다. 정렬은 `latest`, `oldest`, `views`만 허용하며, 잘못된 값과 `constructor`, `__proto__` 같은 상속 속성은 `latest`로 처리합니다. 조회수 동점은 `id DESC`로 정렬합니다.

응답 `meta`에는 `page`, `limit`, `totalCount`, `totalPages`, `offset`, `sort`, `search`, `hasNext`, `hasPrev`, `executionTimeMs`가 포함됩니다.

- `offset = (page - 1) * limit`
- `totalPages = max(1, ceil(totalCount / limit))`
- 페이지는 1 이상으로 보정하고, 존재하는 마지막 페이지보다 크면 마지막 페이지로 보정합니다.
- `limit`은 1~100 범위로 제한합니다.

### 커서 페이지네이션

`GET /api/posts/cursor?cursor=950&limit=10&search=인덱스`

커서 API는 `id DESC` 정렬로 고정합니다. `sort` 선택은 커서 모드에서 비활성화됩니다. 검색 조건과 `id < cursor` 조건을 함께 적용한 다음 `limit + 1`개를 가져옵니다. 실제 응답은 최대 `limit`개이며, 추가 1개가 존재하면 `hasNext=true`입니다. 따라서 전체 개수 조회 없이 다음 페이지 존재 여부를 판단할 수 있습니다.

## 4. 프론트엔드 처리

- 검색 입력은 300ms 디바운스로 묶어 연속 타이핑 중 요청을 줄입니다.
- 입력 변경 즉시 이전 fetch를 `AbortController`로 취소하고 요청 세대 번호도 증가시킵니다. 응답이 이미 도착했거나 취소가 늦은 경우에도 오래된 요청 세대의 응답은 화면에 반영하지 않습니다.
- `AbortError`는 정상적인 취소로 처리하며 사용자 오류로 표시하지 않습니다.
- 검색어 변경 시 페이지를 1로 되돌리고 커서·누적 목록을 초기화합니다.
- 오프셋 모드의 `page`, `sort`, `search`는 `URLSearchParams`로 주소창에 반영됩니다. 새로고침과 뒤로/앞으로 가기에서 URL을 읽어 컨트롤과 결과를 복원합니다.

## 5. 기존 코드 대비 주요 수정

| 파일 | 기존 코드 | 개선 코드 |
|---|---|---|
| `server.js` | `SORT_WHITELIST[sortKey]` 직접 조회 | null-prototype 화이트리스트와 `Object.hasOwn`으로 상속 속성 차단 |
| `server.js` | 커서 API가 ID 조건만 적용 | 검색어를 제목·본문에 적용하고 커서 조건과 결합 |
| `server.js` | 페이지·limit 파싱이 일부 잘못된 문자열을 허용 | 숫자 문자열 검증 후 범위 제한 |
| `index.html` | 커서 요청에 검색어 미전달 | 커서 요청에도 검색어 전달, 검색 변경 시 누적 데이터 초기화 |
| `index.html` | 커서 모드에서도 정렬 선택 가능 | 커서 모드에서 정렬 선택 비활성화, ID 내림차순 고정 안내 |
| `index.html` | Abort만으로 오래된 응답 차단 | AbortController + 요청 세대 번호로 늦은 응답 차단 |
| `index.html` | 검색 버튼과 디바운스 타이머 중복 가능 | 검색 실행 시 타이머 취소, 입력 즉시 이전 요청 취소 |
| `index.html` | URL 초기값 검증이 느슨함 | URL 페이지·정렬 값을 검증하고 컨트롤과 동기화 |

## 6. 테스트 체크리스트

아래 테스트는 브라우저에서 직접 수행하고 실제 결과 및 캡처를 보고서에 기록합니다.

| 항목 | 입력/동작 | 기대 결과 |
|---|---|---|
| 제목 검색 | `B-Tree` | 제목에 검색어가 포함된 글만 표시 |
| 본문 검색 | `상세 본문 데이터` | 본문에 검색어가 포함된 글 표시 |
| 결과 없음 | `없는검색어XYZ` | 결과 없음 안내 표시 |
| 정렬 | latest / oldest / views | 각각 최신순 / 오래된순 / 조회수순, 조회수 동점은 id 내림차순 |
| 정렬 보안 | `sort=constructor`, `sort=__proto__`, `sort=toString`, `sort=invalid` | 오류 없이 latest 적용 |
| 파라미터 | `page=0`, `page=-1`, `page=abc` | 1페이지로 보정 |
| limit 상한 | `limit=1000` | 100개로 제한 |
| 커서 검색 | `/api/posts/cursor?limit=10&search=인덱스` | 제목·본문 검색 후 ID 내림차순으로 반환 |
| 커서 연속 탐색 | 더 보기 반복 | 마지막까지 ID 중복·누락 없이 표시 |
| 디바운스 | 300ms 이내 간격으로 연속 입력 | 마지막 입력 기준 요청 1회 |
| 요청 취소 | 느린 네트워크에서 검색어 연속 변경 | 이전 요청 취소, 최종 검색어 결과 유지 |
| URL 복원 | 검색·정렬·페이지 변경 후 새로고침 및 뒤로 가기 | URL·입력창·정렬·결과 일치 |

## 7. 개념 설명

### 오프셋과 커서에 적합한 화면

오프셋은 페이지 번호를 직접 선택하는 게시판·관리자 목록처럼 특정 페이지로 이동해야 할 때 적합합니다. 커서는 SNS 피드·무한 스크롤처럼 다음 항목을 이어서 읽는 화면에 적합합니다. 커서 방식은 이 예제에서 `id DESC` 기준으로 고정되어 있습니다.

### 디바운스와 요청 취소

디바운스는 사용자가 입력을 잠시 멈춘 뒤 요청을 보내도록 하여 불필요한 API 호출을 줄입니다. 요청 취소는 새 검색이 시작될 때 이전 fetch를 중단합니다. 요청 세대 번호 검사는 취소 직전 이미 완료된 응답이 늦게 화면을 덮어쓰는 경우까지 방지합니다.

### `limit + 1` 원리

화면에 보여줄 `limit`개보다 한 건 더 조회합니다. 조회 결과가 `limit + 1`개라면 다음 페이지가 있으므로 `hasNext=true`이고, 그렇지 않으면 `false`입니다. 실제 화면에는 앞의 `limit`개만 반환합니다.

### offset 및 totalPages 계산

`offset = (page - 1) * limit`은 현재 페이지 이전에 건너뛸 항목 수입니다. `totalPages = max(1, ceil(totalCount / limit))`은 전체 건수를 페이지 크기로 나눈 올림 값이며, 결과가 0일 때도 페이지 메타를 1로 유지합니다.
